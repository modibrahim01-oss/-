# سبّاق (Sabbaq) — نظام تحفيز الطلاب بالنقاط والمزارع الافتراضية

منصة تعليمية تكافئ الطلاب بالنقاط، وكل نقطة تُترجَم بصريًا إلى **نبتة**
تُغرَس تلقائيًا في **مزرعة ثلاثية الأبعاد** خاصة بكل طالب. المزرعة تنمو على
مدى فصل من ٩٠ يومًا وتُعرَض على شاشات المدرسة والجوال **بدون تسجيل دخول**.

المنظور isometric ثابت بأسلوب Clash of Clans: أرضية عشب مبلّطة، جدار حجري
حول الملعب، ونباتات كرتونية سمينة بأربعة أشكال مختلفة تمامًا.

---

## المكدّس التقني

| الطبقة | التقنية | السبب |
|---|---|---|
| الواجهة | Next.js 15 (App Router) + TypeScript | RSC للقراءة، Server Actions للكتابة |
| المزرعة | **Three.js** — كاميرا orthographic | ألف نبتة بـ 60fps؛ DOM/SVG يهبط تحت ٢٠fps عند ٥٠٠ عنصر |
| التنسيق | Tailwind + متغيّرات CSS | ثيم فاتح/داكن، RTL و LTR |
| قاعدة البيانات | PostgreSQL على Supabase | RLS للأدوار، أقفال صفوف لذرّية المنح |
| المصادقة | Supabase Auth — للمشرفين والمدير فقط | الطلاب لا يسجّلون دخولًا |
| الخطوط | Reem Kufi + Tajawal عبر `next/font` | مُستضافة ذاتيًا، بلا انزياح تخطيط |
| النشر | Vercel + Supabase | قراءة كثيفة على الحافة، كتابة متقطّعة |

## التشغيل محليًا

```bash
npm install
cp .env.example .env.local   # ثم عبّئ مفاتيح Supabase
npm run dev
```

### متغيّرات البيئة

| المتغيّر | الوصف |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | رابط مشروع Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | المفتاح العام — يقرأ به الزوار المزارع |
| `SUPABASE_SERVICE_ROLE_KEY` | خادمي فقط: إنشاء حسابات المشرفين من لوحة المدير |

إن نقص أحد الأولين يعرض الوسيط صفحة تشخيص عربية تسمّي المتغيّر الناقص، بدل
انهيار غامض.

### تجهيز قاعدة البيانات

نفّذ ملفات `supabase/migrations/` **بالترتيب** في `SQL Editor`:

```
0001_schema.sql     ٩ جداول + الفهارس + القيود
0002_functions.sql  الخوارزمية الحلزونية، award_points، إدارة الفصول
0003_rls.sql        ٢٠ سياسة RLS + العرض العام student_farms
0004_seed.sql       المجموعات السبع، الحدود، الفصل الأول، trigger المصادقة
```

ثم أنشئ أول حساب مدير من `Authentication ← Users ← Add user` مع
`user_metadata`:

```json
{ "full_name_ar": "اسم المدير", "role": "admin" }
```

الـ trigger في `0004_seed.sql` ينشئ صفّه في `public.users` تلقائيًا. بعدها
يستطيع المدير إنشاء بقية الحسابات من شاشة **المشرفون**.

## الاختبارات

```bash
npm test          # ١٩ اختبار وحدة: الخوارزمية الحلزونية، الفئات، التكافؤ
npm run typecheck
npm run lint
npm run build
npm run shoot     # فحص بصري للمزرعة في Chromium (يحتاج dev server)
npm run test:db   # ٤٨ توكيد عزل على Postgres حقيقي
```

### اختبارات العزل على قاعدة بيانات حقيقية

`٤٨ توكيدًا` تعمل على Postgres محلي عبر محاكاة بيئة Supabase
(`auth.uid()`، دور `authenticated` و `anon`، جدول `auth.users`):

```bash
PGHOST=/tmp PGPORT=5432 PGUSER=postgres npm run test:db
```

ما يتحقّق منه **فعليًا باستعلامات SQL مباشرة، لا بالواجهة**:

- مشرف المجموعة لا يستطيع منح نقاط لطالب خارج مجموعته — ولا صف يتسرّب
- الحد اليومي صارم: المنح الذي يتجاوزه يُرفض، والذي يبلغه بالضبط يُقبل
- المشرف المستنفد لا يمرّر حتى أصغر فئة
- **لا insert مباشر على `points_ledger` لأي مشرف** — المنح يمرّ عبر
  `award_points` وحده، وهو ما يمنع تجاوز الحد بـ SQL يدوي
- العامّة (`anon`) تقرأ المزارع بلا حساب، ولا تكتب ولا تعدّل شيئًا
- المدير معفى من الحد، وكل تجاوزاته مسجّلة باسمه
- النبتة الأولى في المركز `(0,0)` بالضبط، والخانات متتالية بلا فراغ ولا تكرار
- خانة مكرّرة لنفس الطالب يرفضها قيد `unique` — خط الدفاع الأخير خلف القفل
- السحب للمدير وحده، **ولا يُفرِج عن الخانة** فلا تتزحزح بقية النبتات
- رفع الحد يُفرج فورًا عن مشرف كان قد استنفده
- الأرشفة تحفظ لقطة لكل طالب، والتصفير يُرجع المزارع للمركز ويُبقي السجل
- المشرف لا يرى بقية المشرفين ولا سجل التدقيق

الملف **قابل لإعادة التشغيل**: يُصفّر المفاتيح الأجنبية قبل حذف المستخدمين،
وأُثبت ذلك بتشغيلين متعاقبين بنفس النتيجة.

### الفحص البصري للمزرعة

محرّك WebGL لا تغطّيه اختبارات الوحدة: مشهد سليم منطقيًا قد يُرسَم بارتفاع
صفر أو بتأطير يقطع نصف المزرعة، وكلاهما يمرّ من البناء والنوع واللينت بلا
شكوى. الفحص يفتح المزرعة في Chromium فعليًا:

```bash
npx next dev -p 3312 &
npm run shoot            # يحفظ ٤ لقطات ويخرج بخطأ إن انهار الـ canvas
```

يغطّي: ١٢٠ نبتة، ٦٠٠ نبتة (كثافة فصل كامل)، وضع الشاشات الليلي، وشاشة جوال
٣٩٠px. تحقّقتُ أنه ليس فحصًا فارغًا بإعادة إدخال عطب الانهيار — فرصده في
الحالات الأربع وخرج بمخرَج غير صفري.

**عطبان حقيقيان اكتشفهما هذا الفحص بعد أن مرّا من كل ما سبق:**

1. **الـ canvas كان يُرسَم بارتفاع صفر.** جذر `FarmScene` كان يضبط
   `position: relative` سطريًا، والسطري يتغلّب على `position: absolute`
   القادم من صنف المستدعي، فبطل مفعول `inset: 0` وانهار العنصر. المزرعة
   كانت شريطًا بلا ارتفاع في صفحة الطالب ووضع الشاشات معًا.
2. **التأطير كان ثابتًا.** تكبير واحد يصلح لعشرات النبتات ويفشل لمئاتها:
   طالب بعد فصل كامل يفتح مزرعته فيرى زاويةً منها. الكاميرا الآن تؤطّر
   السياج كاملًا عند الفتح، والسياج نفسه يتوسّع مع نمو المزرعة.

### تكافؤ الخوارزمية بين الخادم والعميل

قاعدة البيانات تحسب إحداثيات النبتة وقت المنح، والمتصفح يرسمها. لو تباعدت
النسختان ظهرت النبتة في غير موضعها وتراكبت نبتتان. لذلك:

- `spiral_coord` في SQL و `spiralCoord` في TypeScript **مُطابِقتان حرفيًا**
- `tests/spiral-parity.test.ts` يقارنهما على **٣٠٠٠ خانة** من مخرَج Postgres
  الحقيقي المحفوظ في `tests/fixtures/sql-spiral.csv`
- `npm run test:db` يُعيد توليد الملف المرجعي، فأي انحراف يظهر كفشل اختبار

## محرّك المزرعة

### التوزيع الحلزوني

حلزون مربعي (Ulam) يبدأ من المركز ويتوسّع للخارج طبقة طبقة، فيملأ الشبكة بلا
فراغات ولا تكرار. الطالب **لا يضع نبتته**: الخانة تُحجَز في قاعدة البيانات
وقت المنح.

```
الطبقة k تسع (2k+1)² خانة تراكميًا
٩٠ يومًا × ٢٠ نبتة = ١٨٠٠ نبتة → الطبقة ٢٢ (٢٠٢٥ خانة) تكفيها
```

الخانة تُحجَز تحت **قفل صف الطالب** (`select … for update`) داخل
`award_points`، فمشرفان يضغطان على نفس الطالب في نفس اللحظة يتسلسلان ولا
يحصلان على نفس الإحداثيات. وراء القفل قيد
`unique (student_id, semester_id, slot_index)` كخط دفاع أخير.

### فئات النقاط

| النقاط | النبتة | الشكل المجسّم |
|---|---|---|
| ١٠ | شجيرة | ثلاث كرات خضراء متداخلة + حبّات حمراء |
| ٢٠ | زهور | ثلاث توليبات صفراء بمخاريط + ورقتان |
| ٣٠ | فطر | فطر كبير وصغير بقبّة بنفسجية ونقاط بيضاء |
| ٥٠ | شجرة مثمرة | جذع + تاج أخضر بتدرّجين + خمس فواكه حمراء |

كل فئة **كائن مختلف تمامًا** لا لونًا مختلفًا فقط، فتُقرأ قيمة النبتة من
شكلها عن بعد على شاشة المدرسة.

### الكاميرا والملعب

كلاهما يتكيّف مع حجم المزرعة:

- **السياج يتوسّع مع النمو** (`playHalfFor`): يحيط بأبعد نبتة بهامش ثلاث
  بلاطات. ملعب ثابت الحجم يجعل مزرعة صغيرة بقعة تائهة وسط عشب فارغ،
  ومزرعة كبيرة محشورة في سياجها.
- **التأطير عند الفتح** (`fitToPlants`): يحسب قطر المعيّن في الإسقاط
  المتساوي القياس ويضبط التكبير ليدخل كاملًا. زر «إعادة الضبط» يرجع لهذا
  الإطار لا لتكبير ثابت.
- **على الشاشة الطولية** يُسمح بقصّ طرفَي الجزيرة (زاويتاها عشب بلا نبتات)،
  وإلا فرض عرضُ المعيّن ارتفاعَ عرضٍ مضاعفًا فانحصرت المزرعة في شريط بربع
  ارتفاع الشاشة.

الهندسات والموادّ في `src/lib/plants.ts` تُنشأ **مرة واحدة وتُشارَك** بين كل
النبتات؛ إنشاء موادّ لكل نبتة ينهار عند بضع مئات.

## نهاية الفصل

شاشة **الفصول** تعطي المدير خيارين مستقلّين:

- **أرشفة**: لقطة كاملة (اسم، مجموعة، نقاط، نبتات) لكل طالب في
  `semester_archives`. المزارع تبقى كما هي.
- **تصفير**: كل المزارع ترجع للمركز ويبدأ فصل جديد. **سجل النقاط التفصيلي
  يبقى محفوظًا** مرتبطًا بمعرّف الفصل السابق.
- **الاثنان معًا**: الاستخدام المعتاد — يؤرشف ثم يصفّر.

التصفير بلا أرشفة يعرض تحذيرًا صريحًا، وكلا الإجراءين يطلب كتابة «تأكيد»
يدويًا لأنهما يمسّان كل طالب في المدرسة.

## قرارات تصميمية تستحقّ التوضيح

1. **`points_ledger` لا يُكتب إليه مباشرة أبدًا** — ولا حتى من المشرف عبر
   RLS. المنح يمرّ عبر `award_points` وحده لأنه الوحيد الذي يضمن ذرّية
   الحد اليومي وحجز الخانة. بدون هذا القيد يستطيع مشرف أن يُدرج صفًّا
   بإحداثيات من اختياره ويتجاوز حدّه بـ SQL يدوي.

2. **السحب ناعم ولا يُفرِج عن الخانة.** إعادة ترقيم الخانات بعد سحب نقطة
   واحدة تُزحزح كل نبتة بعدها، فيتغيّر شكل المزرعة كلها. الخانة تبقى
   محجوزة والنبتة وحدها تختفي.

3. **المدير معفى من الحد اليومي.** الوثيقة تمنحه حق التجاوز والتعديل العام،
   والبديل (حدّ للمدير) يعطّل تصحيح الأخطاء نهاية اليوم. كل ما يمنحه
   مسجّل باسمه في `points_ledger` و `audit_log`.

4. **إخفاء الطالب لا حذفه.** الحذف يُسقط سجل نقاطه بـ cascade فتضيع مساهمة
   المشرفين من الإحصاءات. `is_active = false` يُخرجه من القوائم ويُبقي
   التاريخ.

5. **اللغة في كوكي لا في المسار.** المزارع تُعرض على شاشات برابط محفوظ،
   وتغيير اللغة لا يجب أن يبدّل ذلك الرابط.

6. **`student_farms` عرض بـ `security_invoker = true`.** بدونه تُنفَّذ
   استعلاماته بصلاحيات مالكه متجاوِزةً RLS بالكامل.

7. **تخزين مؤقت متباين حسب الصفحة**: المزرعة ٣٠ ثانية، الصفحة العامة ٦٠،
   ووضع الشاشات يُعيد الجلب كل ٥ دقائق من المتصفح. شاشة معلّقة في ممر لا
   يجب أن تكون استعلامًا على قاعدة البيانات كل ثانية.

## ما لم يُبنَ بعد

- **تقارير مفصّلة**: اللوحة تعرض أفضل ١٠ طلاب وأعلى مجموعة؛ الرسوم البيانية
  الزمنية ومقارنة المجموعات لم تُبنَ.
- **استيراد ملف Excel مباشرة**: الحالي يقبل **لصق** الصفوف مع معاينة قبل
  الإدراج. قراءة `.xlsx` نفسه (`exceljs` مثبَّت) لم تُوصَل بالواجهة.
- **تحديث فوري (Realtime)**: وضع الشاشات يستقصي كل ٥ دقائق بدل قناة
  Supabase Realtime.
- **تجربة المسار كاملًا على بيانات حقيقية**: المزرعة نفسها مفحوصة بصريًا في
  Chromium، وسياسات العزل مفحوصة على Postgres حقيقي، لكن **الرحلة الكاملة
  عبر Supabase** (مشرف يسجّل دخوله ← يمنح نقطة ← الطالب يراها في مزرعته)
  لم تُجرَّب لأنها تحتاج مشروع Supabase فعليًا. أجزاؤها مفحوصة كلٌّ على
  حدة؛ ما لم يُختبَر هو الوصلات بينها عبر الشبكة.
