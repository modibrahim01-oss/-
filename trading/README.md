# دفتر التداول — موقع متابعة التداول اليومي

تطبيق ويب شخصي (مستخدم واحد، بلا خادم) لتسجيل صفقات التداول اليومي واستخراج
رصيد المحفظة والأرباح والنسب تلقائياً، مع جدول توقّع رياضي للمقارنة.

عربي بالكامل، اتجاه RTL، مصمّم من شاشة الجوال أولاً، ويعمل بلا إنترنت بعد أول
فتحة (PWA قابل للإضافة لشاشة الجوال).

---

## التشغيل

```bash
npm install
npm run dev        # خادم تطوير
npm test           # اختبارات طبقة الحسابات والتخزين
npm run typecheck  # فحص الأنواع
npm run build      # مجلد dist جاهز للنشر
npm run preview    # معاينة مخرجات البناء
```

## النشر

المخرجات في `dist/` ملفات ثابتة — تُرفع كما هي إلى Netlify أو Vercel أو أي
استضافة ثابتة.

| الإعداد | القيمة |
|---|---|
| مجلد الجذر | `trading` |
| أمر البناء | `npm run build` |
| مجلد النشر | `dist` |

التنقّل عبر `hash` (`#/log`)، فلا يحتاج الخادم أي إعادة توجيه.

## قرارات تستحق المعرفة قبل التعديل

**كل حساب يجري بالهللات كأعداد صحيحة.** `320 ريال = 32000`. التحويل من/إلى
الريال يحدث في `money.ts` وحده. لا تضرب ولا تقسم مبلغاً خارج هذا الملف، وإلا
عادت أخطاء الفاصلة العائمة تتراكم عبر أيام السجل.

**الإيداعات ليست ربحاً.** `balance = رأس المال + صافي الإيداعات + مجموع نتائج
الصفقات`، بينما `الربح = مجموع نتائج الصفقات` فقط. أي رقم ربح جديد يجب أن يطرح
صافي الإيداعات. هذا أكثر خطأ متوقع في هذا النوع من التطبيقات، وهناك اختبار
يحرسه.

**السجل مشتقّ بالكامل ويُبنى من الصفر.** `buildLedger` لا يحفظ رصيداً ولا يحسب
تفاضلياً، فتعديل صفقة قديمة أو حذفها يعيد حساب كل الأيام اللاحقة تلقائياً.
حجم البيانات (مئات السجلات) يجعل هذا أرخص من أي بديل.

**اليوم الخالي غير موجود.** يظهر في السجل فقط اليوم الذي فيه صفقة أو حركة نقدية
أو تسوية. رصيد الافتتاح هو إقفال آخر يوم فيه حركة، لا اليوم السابق تقويمياً.

**الرسوم تجري من اليمين إلى اليسار.** الأقدم يميناً والأحدث يساراً، ومحور القيم
على اليمين — اتساقاً مع اتجاه القراءة. إن أردت العكس: احذف `reversed` من محاور
`XAxis` في `screens/Charts.tsx`، وأعد `x` في `components/Sparkline.tsx` إلى
`(index / (values.length - 1)) * width`.

**النسبة الإجمالية أساسها رأس المال + صافي الإيداعات**، لا رأس المال وحده — حتى
لا يبدو العائد أكبر مما هو بعد كل إيداع. الأساس معروض صراحةً في الشاشة الرئيسية.

## البيانات والنسخ الاحتياطي

البيانات تعيش في `localStorage` في متصفح واحد فقط. لا خادم ولا حساب ولا نسخة
سحابية. مسح بيانات المتصفح أو تغيير الجهاز يعني فقدانها.

خطة الأمان الوحيدة هي التصدير: زر **نسخة احتياطية (JSON)** في أعلى شاشة
الإعدادات، وهو الملف الوحيد الذي يعيد التطبيق كما كان. يوجد أيضاً تصدير CSV
للصفقات وللسجل اليومي (بترميز UTF-8 مع BOM ليفتحه إكسل بالعربية سليمة).

الاستيراد يرفض أي ملف بصيغة خاطئة أو `schemaVersion` مختلف **دون أن يمسّ
البيانات الحالية**.

## الأيقونات

`node scripts/make-icons.mjs` يولّد أيقونات PWA بصيغة PNG بلا أي اعتماد خارجي.
شغّله فقط إن غيّرت ألوان الهوية.

## خارج النطاق

لا تسجيل دخول، ولا حسابات متعددة، ولا نظام عمولات كامل (يكفي حقل `feesSAR`
الاختياري وميزة فرق التسوية)، ولا تنبيهات، ولا أسعار سوق مباشرة، ولا توصيات
آلية.
