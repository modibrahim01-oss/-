# CLAUDE.md — سَبْق، مجمع أبي يوسف القرآني

اسم المشروع «سَبْق» (كان يُسمّى «البرنامج التحفيزي» في نسخة سابقة — أي أثر متبقٍّ لذلك الاسم في الكود أو الملفات خطأ يجب تصحيحه).

## ما هو المشروع

تطبيق ويب من صفحة واحدة لمتابعة طلاب حلقات تحفيظ القرآن. المعلم يقيّم طلاب حلقته يوميًا بأربع أدوات (حفظ، مراجعة، حضور، انضباط)، فتُحسب نقاط ويرتفع «مسار التقدم»، ومن بلغ الهدف تأهّل لسحب على جائزة. الواجهة عربية بالكامل (RTL)، والجمهور الأساسي يستخدمها من الجوال.

**لا يوجد نظام بناء.** المشروع ملف HTML واحد فيه CSS وJS مضمّنان، يُرفع كما هو إلى أي استضافة ثابتة. أي اقتراح يضيف npm أو bundler يجب أن يُطرح على المالك أولًا، لأن بساطة النشر مقصودة.

## الملفات

```
index.html            التطبيق كاملًا (~1400 سطر): CSS مضمّن + <script type="module">
logo-abi-yusuf.png    الشعار 256×256، يُستخدم أيضًا كأيقونة وصورة مشاركة
schema.sql            جداول Supabase وسياسات RLS والدوال — يُلصق في SQL Editor
دليل-الإعداد.md        دليل الإعداد والنشر للمالك (عربي، غير تقني)
```

**الواجهة الخلفية: Supabase (Postgres).** كانت Firebase في نسخة سابقة وحُوّلت. أي أثر متبقٍّ لـ Firebase في الكود خطأ يجب حذفه.

## البنية داخل index.html

سكربت الوحدة مقسوم إلى ثمانية أقسام معلّمة بتعليقات مرقّمة — حافظ على هذا الترتيب عند الإضافة:

1. إعدادات Supabase (`SUPABASE_URL` و `SUPABASE_ANON` — مفاتيح عامة بالتصميم، الحماية في RLS)
2. ثوابت ودوال مساعدة (تواريخ، تنسيق عربي، تطبيع نص)
3. طبقة البيانات: `supabaseStore()` و `localStore()` خلف واجهة واحدة، مع مبدّلَي أسماء الحقول `toRow`/`fromRow`
4. الحالة والحسابات (`state`، `calc`، `dayPoints`، `cycleDays`)
5. عناصر واجهة عامة (`toast`، `confirmDialog`، `setSync`، `show`)
6. دوال الرسم (`renderHome`، `renderStudent`، `renderAdmin`، `renderTeacher`، `renderResults`، `evalCard`)
7. الإجراءات (إضافة/حذف/نقل/سحب/نسخ احتياطي)
8. الربط والإقلاع

## طبقة البيانات

الواجهة نفسها في الوضعين، والفرق أن `cloudStore` يستخدم Firestore و`localStore` يستخدم `localStorage`:

```js
store.subscribe(callbacks, onError)   // اشتراك لحظي: settings, stages, circles, students, teachers
store.onAuth(cb)                      // { uid, email, role } أو null
store.signIn(email, pass) / store.signOut()
store.createTeacherAccount(email, pass) → uid
store.saveSettings(patch)
store.put(collection, id, data)       // دمج
store.remove(collection, id)
store.setRecord(studentId, dayKey, rec)
store.replaceAll(data)                // للاستيراد
```

**الوضع المحلي يعمل تلقائيًا** إذا كانت المفاتيح فارغة أو فشل الاتصال بـ Supabase (مشروع موقوف، شبكة مقطوعة)، مع شريط تنبيه في الأعلى. لا تحذف هذا المسار — هو ما يجعل الملف قابلًا للتجربة والاختبار الآلي بلا حساب، وهو أيضًا ما يمنع الشاشة البيضاء إذا توقف المشروع المجاني.

التطبيق يستخدم camelCase وقاعدة البيانات snake_case؛ التحويل في `K2R`/`R2K` داخل طبقة البيانات وحدها. لا تسرّب أسماء الأعمدة إلى بقية الكود.

البث اللحظي عبر `postgres_changes`، وعند أي تغيير يُعاد جلب الجدول كاملًا بتأخير ٢٥٠ مللي ثانية — أبسط من الدمج التدريجي وكافٍ لهذا الحجم. توجد شبكة أمان: إعادة جلب كل دقيقتين وعند عودة التبويب للظهور.

## نموذج البيانات (Postgres)

```
program   (id text pk = 'main', goal, cycle_length, cycle_start date, points jsonb, raffle_history jsonb)
stages    (id uuid pk, name, sort)
circles   (id uuid pk, name, stage_id → stages, sort)
admins    (id uuid pk → auth.users, name)
teachers  (id uuid pk → auth.users, name, email, circle_ids uuid[])
students  (id uuid pk, name, circle_id → circles, stage_id → stages, sort, records jsonb)
```

سجل اليوم الواحد داخل `records`:

```js
records["2026-09-02"] = {
  h: 1.5,                    أوجه الحفظ، بخطوات 0.5، الحد الأعلى MAX_PAGES = 10
  r: 2,                      أوجه المراجعة، نفس القيود
  a: "present"|"late"|"absent"|"",
  d: { g: true, u: false }   الانضباط العام، الزي
}
```

`stage_id` مكرّرة على الطالب عمدًا (مشتقة من حلقته) لتبسيط الترشيح والسحب على مستوى المرحلة. عند نقل طالب بين الحلقات يجب تحديث الحقلين معًا — انظر `moveStudent`.

المعرّفات **يجب أن تكون UUID صالحة** لأن Postgres يرفض غيرها. `uid()` تولّدها، و`importBackup` تعيد توليد أي معرّف غير صالح مع إعادة ربط المراجع.

## الأمان — في قاعدة البيانات لا في الواجهة

RLS مفعّلة على كل الجداول. المنطق في `schema.sql`:

- `program`, `stages`, `circles`, `students`: قراءة عامة (`using (true)`) وكتابة للمشرف وحده عبر `is_admin()`.
- `teachers`: يقرؤه المشرف، ويقرأ المعلم صفَّه فقط — حتى لا تُكشف بُرد المعلمين للطلاب.
- `admins`: بلا أي سياسة، فلا قراءة ولا كتابة من الموقع. يُدار من SQL Editor وحده، وهذا ما يمنع ترقية النفس.

دوال `security definer` تكسر التكرار اللانهائي في السياسات: `is_admin()`، `my_circles()`، `my_role()`.

**المعلم لا يكتب في `students` مباشرة قط.** التقييم يمر عبر `set_record(p_student, p_day, p_rec)` — دالة `security definer` تتحقق من أن الطالب في حلقة المعلم، وتتحقق من صيغة التاريخ، وتنقّي القيم (تحصر الأوجه بين ٠ و١٠، وتقبل الحضور `present/late/absent/excused` فقط) قبل الحفظ. أي تعديل على شكل السجل يجب أن يُعدَّل في الدالة أيضًا وإلا سُقطت الحقول الجديدة بصمت.

**تعديل الشعلة اليدوي محمي بدالة منفصلة أيضًا:** `set_streak_override(p_student, p_value, p_reason)` — ترفض غير المشرف، وترفض سببًا فارغًا، وتكتب سجل تدقيق كامل في جدول `streak_overrides` (لا يُكتفى بآخر قيمة) قبل تحديث `students.streak_override`. لا تسمح لأي دالة أو سياسة أخرى بالكتابة المباشرة في `streak_override`.

حسابات المعلمين تُنشأ من الموقع عبر عميل Supabase ثانٍ بـ `storageKey` مختلف و`persistSession:false`، حتى لا يستبدل `signUp` جلسة المشرف. لا تستبدل هذا باستدعاء `signUp` على العميل الأساسي.

يتطلب هذا إطفاء **Confirm email** في إعدادات Supabase، وإلا لم يستطع أي معلم أو مشرف ثانٍ الدخول.

**تسجيل دخول المشرف الأول برمز واحد لا ببريد وكلمة مرور.** الحيلة: بريد ثابت غير سرّي `ADMIN_EMAIL = "admin@sabaq.local"` مكتوب في الكود، وما يكتبه المشرف في الواجهة هو كلمة المرور الفعلية لذلك الحساب — يتحقق منها Supabase Auth نفسه (مُجزّأة في قاعدة البيانات)، فلا يظهر الرمز في الكود أبدًا خلافًا لنظام الـ PIN القديم. لدعم مشرف ثانٍ بحساب مستقل توجد شاشة بديلة (بريد + كلمة مرور) خلف رابط "مشرف آخر؟" — لا تحذفها ظنًّا أنها زائدة عن نظام الرمز.

## قواعد العمل — لا تغيّرها دون طلب صريح

**أيام الحلقة:** الأحد إلى الأربعاء فقط (`SESSION_WEEKDAYS = [0,1,2,3]`). الخميس والجمعة والسبت أيام توقف: لا يُسجَّل فيها شيء، ولا تكسر مسار التقدم، ولا تُحتسب في طول الدورة.

**النقاط** (`dayPoints`):

| العنصر | النقاط |
|---|---|
| كل نصف وجه حفظ | 50 (أي `h * 2 * points.half`) |
| كل وجه مراجعة | 150 |
| حضور مبكر / متأخر / غائب / معذور | 100 / 50 / 0 / 0 |
| الانضباط العام | 75 |
| الزي | 25 |

القيم كلها قابلة للتعديل من لوحة المشرف وتُخزَّن في `program/main.points`. النقاط **محسوبة لا مخزّنة**: تغيير القيم يعيد حساب كل التاريخ تلقائيًا. لا تُدخل حقل نقاط مخزّن في مستند الطالب.

**يوم بعذر** (`a: "excused"`) حالة خاصة: `dayPoints` تُرجع صفرًا فورًا بلا حساب أي عنصر، و`calc` تتخطى اليوم بالكامل (`continue`) فلا يُضاف لنقاط الدورة أو التراكمية، **ولا يكسر مسار التقدم ولا يزيده** — يُعامَل كأن اليوم لم يكن من أيام الحلقة لهذا الطالب وحده.

**أيام العطل الرسمية** (إجازة وزارية، مطر، غبار…): يُعلنها المشرف من تبويب «الإعدادات والسحب» → قسم «أيام العطل والإجازات». تختلف عن «معذور» بأنها تخصّ **كل الطلاب دفعة واحدة**. تُخزَّن داخل عمود `program.points` تحت مفتاح محجوز `_holidays` = `[{ date, reason }]` (لتفادي `ALTER TABLE`). تخطّي العطلة يحدث في `cycleDays()` (تُستبعد كأن اليوم يوم توقف) وفي `calc()` التراكمية (السجلات المكتوبة قبل إعلان العطلة تُلغى بأثر رجعي دون حذفها). **تنبيه صيانة:** أي كتابة على `points` يجب أن تُبقي `_holidays` وإلا مُسحت العطل بصمت — انظر `savePoints()` كمرجع.

**مسار التقدم** (`qualifies` + `calc`): يزيد يومًا إذا `h > 0` **و** الحضور `present` أو `late` (الأيام المعذورة تُتخطّى قبل هذا الشرط). المراجعة والانضباط لا يؤثران فيه. إذا فات يوم حلقة دون استيفاء الشرط (وليس معذورًا) عاد المسار إلى الصفر — **لكن النقاط المكتسبة سابقًا تبقى كما هي ولا تُمسّ**. هذا مطلب صريح من المالك.

يوم اليوم لا يكسر المسار قبل انتهائه: في حلقة `calc` الشرط `else if(k !== tk) streak = 0`.

**تعديل الشعلة يدويًا** (`streakOverride` على الطالب، عمودها `streak_override` في القاعدة): يُقرأ في `calc()` بعد الحلقة الحسابية، ويُستبدل به `streak`/`best` **فقط إذا كان `ov.cycle` يطابق `cycleStart` الحالي** — بدء دورة جديدة يُسقط أي تعديل قديم تلقائيًا دون حذفه من سجل التدقيق. النقاط (`cyclePts`, `total`) لا يمسّها التعديل اليدوي إطلاقًا، فهو يغيّر رقم المسار المعروض فقط.

**قفل تعديل المعلم:** `renderEvalList` تحسب `locked = editable && state.user?.role !== "admin" && key !== todayKey()`. أي يوم غير اليوم الحالي يُقفل تمامًا أمام المعلم (لا حتى داخل نفس اليوم بعد منتصف الليل، بل أي يوم سابق). المشرف بلا قيد إطلاقًا. لا تُلغِ هذا الشرط بحجة "تجربة مستخدم أفضل" دون طلب صريح — قفل صارم مطلوب من المالك.

**التأهل:** `best >= goal` حيث `best` أعلى مسار بلغه الطالب في الدورة الحالية، لا المسار الحالي. أي أن من بلغ الهدف يبقى مؤهلًا حتى نهاية الدورة ولو انقطع بعدها.

**السحب:** مستقل لكل مرحلة، ويمكن تكراره أكثر من مرة في الدورة نفسها (تغيير صريح من المالك، كان سابقًا مرة واحدة فقط). الاختيار عشوائي دائمًا (`Math.random()` من المؤهّلين الذين لم يفوزوا بعد في هذه الدورة — `wonIds` مبنية من `raffleHistory` بمطابقة `studentId`)، ولا اختيار يدوي. زر «ابدأ» يشغّل شريطًا متحركًا (ريلّ) يعرض كل طلاب المرحلة مرتّبين بنقاطهم التراكمية، يدور بلا توقف تلقائي حتى يضغط المشرف «إيقاف» — حينها فقط يُحسم الفائز.

**بدء دورة جديدة:** يغيّر `cycleStart` فقط. السجلات والنقاط التراكمية وسجل تدقيق الشعلة كلها تبقى.

## الأدوار

- **الطالب**: بلا حساب، قراءة فقط، يبحث عن اسمه في قائمة موحّدة (تقرر صراحةً عدم بناء حسابات فردية للطلاب — لا تُعِد طرح الفكرة دون طلب).
- **المعلم**: صف في `teachers`، يقيّم طلاب حلقاته في `circle_ids` فقط ويرى نتائجهم، ويُقفل تعديله لغير يوم اليوم.
- **المشرف**: صف في `admins` يُنشأ من SQL Editor. يملك كل شيء بلا قيد زمني، ويدخل برمز واحد (انظر قسم الأمان).

الدور يُحدَّد بعد تسجيل الدخول باستدعاء `rpc("my_role")`، لا بقراءة الجداول.

## عادات الكود

- `<script type="module">`، بلا `onclick` مضمّن في HTML. الربط بـ `addEventListener` أو `element.onclick` في القسم الثامن.
- كل نص من المستخدم يمر بـ `esc()` قبل `innerHTML`، أو يُضاف بـ `textContent`.
- مفاتيح التواريخ تُبنى بـ `dayKey()` من `getFullYear/getMonth/getDate` محليًا. **لا تستخدم `toISOString()` لمفتاح تاريخ** — يزيح اليوم قبل الساعة ٣ فجرًا بتوقيت الرياض. هذا خطأ سابق أُصلح.
- ربط المعلم بالحلقة يُخزَّن في `teachers.circle_ids` فقط. لا تُعِد إضافة `teacher_uid` على `circles` — كانت تكرارًا يقع في التناقض.
- الأرقام المعروضة تمرّ بـ `nf.format()` (أرقام عربية-هندية) لتتسق مع التواريخ الهجرية.
- العدد + كلمة «يوم» عبر `daysPhrase()`، والأوجه عبر `pagesPhrase()` — القواعد العربية تختلف بين ١ و٢ و٣-١٠ وما فوق. لا تكتب `${n} يومًا` مباشرة.
- التقويم: **هجري** في واجهة الطالب (`fmtHijriDay`، `fmtHijriLong` بلاحقة `-u-ca-islamic-umalqura` صراحةً)، **ميلادي** في لوحتَي المشرف والمعلم. لا تعتمد على `ar-SA` وحدها — تقويمها يختلف بين المتصفحات.
- البحث عن الأسماء يمرّ بـ `normalizeAr()` (همزات، تاء مربوطة، ألف مقصورة، تشكيل).
- التقييم يُحفظ تلقائيًا بتأجيل ٦٠٠ مللي ثانية (`queueSave`) حتى لا نكتب مع كل ضغطة على `+`. الواجهة تتحدث فورًا والكتابة تتأخر.

## أخطاء أُصلحت — تحقق منها قبل أي إصدار

1. مفاتيح التواريخ محلية لا UTC.
2. البحث العربي مطبَّع.
3. السحب محروس ضد فوز نفس الطالب مرتين في الدورة نفسها (لا ضد تكرار السحب — يمكن السحب أكثر من مرة لكل مرحلة، انظر «قواعد العمل»).
4. حذف كل الطلاب لا يمسح `raffleHistory` ولا `cycleStart`.
5. الحفظ تلقائي — لا زر «حفظ» يوهم بأن التعديلات محفوظة وهي ليست كذلك.
6. الأوسمة وشروط التأهل تقرأ `state.settings.goal` لا رقمًا ثابتًا.
7. `<noscript>` موجود، ووسوم `og:` موجودة.
8. لا تجاوز أفقي على عرض 390px.
9. رمز المشرف لا يظهر في الكود أبدًا — يُتحقق منه عبر Supabase Auth، لا عبر ثابت JS مقروء بـ "عرض المصدر" (كان هذا عيب نسخة PIN القديمة، لا تُعِده).
10. تعديل الشعلة اليدوي **مسجَّل ومُبرَّر دائمًا**، لا رقمًا صامتًا بلا مصدر.

## الاختبار

لا يوجد إطار اختبار مثبّت. الطريقة المتبعة: خادم محلي + Puppeteer على الوضع المحلي، مع زرع بيانات في `localStorage` تحت المفتاح `aby_yusuf_tahfizi_v3` ثم إعادة تحميل الصفحة. الوضع المحلي يعمل تلقائيًا حين يتعذّر الوصول إلى Supabase، **ويمنح دور admin دائمًا** — فلا يصلح لاختبار قفل المعلم أو صلاحياته، وهذا يحتاج مشروع Supabase فعليًا أو محاكيًا محليًا.

```bash
python3 -m http.server 8899 --bind 127.0.0.1
```

اضبط منطقة زمنية `Asia/Riyadh`، وتحقق دائمًا من: صحة `dayPoints` برقم محسوب يدويًا، وانكسار مسار التقدم عند الغياب مع بقاء النقاط وبقاء التأهل، وأن يوم بعذر لا يكسر المسار ولا يغيّر النقاط، وخلوّ الكونسول من الأخطاء، وأن `scrollWidth - clientWidth === 0` على 390px.

**الأولوية القصوى المطلوبة:** سياسات RLS ودوال `set_record`/`set_streak_override` لم تُختبر تنفيذيًا قط. شغّل `supabase start` محليًا واكتب اختبارات تثبت:

- المعلم يستدعي `set_record` لطالب في حلقته ✓، ويُرفض على طالب من حلقة أخرى ✗
- المعلم يُرفض عند `update` مباشر على `students`، وعلى `program`/`stages`/`circles`
- المعلم يُرفض عند استدعاء `set_streak_override` أيًّا كان الطالب (للمشرف وحده) ✗
- `set_streak_override` ترفض سببًا فارغًا، وتكتب صفًا في `streak_overrides` مطابقًا للقيمة المحفوظة
- `anon` يقرأ الطلاب ولا يكتب، ولا يقرأ `admins` ولا `streak_overrides`
- المعلم لا يقرأ صف معلم آخر ولا جدول `streak_overrides`
- `set_record` ترفض تاريخًا بصيغة خاطئة، وتحصر الأوجه ضمن ٠–١٠، وتقبل `excused` ضمن الحضور
- تسجيل الدخول بالرمز الخاطئ على `admin@sabaq.local` يُرفض دون كشف أي معلومة عن وجود الحساب من عدمه

## النشر

رفع `index.html` و `logo-abi-yusuf.png` معًا في نفس المجلد إلى أي استضافة ثابتة (Netlify Drop، Vercel، GitHub Pages). لا خطوة بناء. المفاتيح في الكود عامة بالتصميم ولا تُخفى.

## قرارات محسومة — لا تُعِد طرحها كأسئلة مفتوحة

- **لا حسابات للطلاب.** بُحث الخيار صراحةً وقُرر الإبقاء على البحث في قائمة موحّدة بلا تسجيل دخول. لا تقترح "تسجيل دخول للطالب" كتحسين إلا إذا طلب المالك ذلك بنفسه.
- **الشعلة لا تُحسب من الصفر تلقائيًا إلا بالغياب الحقيقي.** الأعذار والتعديل اليدوي هما الاستثناءان الوحيدان المتفق عليهما.
- **قفل المعلم صارم عند منتصف الليل بلا مهلة إضافية.** طُرح بديل (مهلة حتى يوم الحلقة التالي) ورُفض صراحةً.

## مسائل معلّقة — اطرحها على المالك قبل تنفيذها، لا تفترض إجابتها

- **موعد السحب القادم:** هل يُحسب تلقائيًا من طول الدورة وتاريخ بدايتها، أم يكتبه المشرف يدويًا؟ لم يُحسم.
- **عرض المنافسين للطالب** (في حلقته وفي مرحلته): هل يُعرض الترتيب كاملًا أم أفضل عشرة + ترتيب الطالب نفسه فقط؟ اقتراح سابق بالثاني تفاديًا لإحباط المتأخرين، لم يُقرَّر بعد.
- أربعة أقسام في مواصفات المشرفين ما زالت فارغة (تفاصيل النقاط، سير البرنامج، استشكالات، ملاحظات وتوصيات) — لا تبنِ عليها شيئًا حتى تُملأ، فقد تغيّر حسبة النقاط الحالية.

## مهام مقترحة لم تُنفّذ بعد

- اختبارات RLS و`set_record`/`set_streak_override` على محاكي Supabase (الأهم).
- منع توقف المشروع المجاني بعد ٧ أيام خمول: مراقب خارجي (UptimeRobot) أو مهمة مجدولة تلمس قاعدة البيانات.
- العمل دون اتصال: طابور كتابة في IndexedDB + Service Worker، ليقيّم المعلم والتغطية ضعيفة في المسجد وتُرفع البيانات لاحقًا. Supabase لا يوفّر هذا جاهزًا بخلاف Firestore، فيحتاج بناءً يدويًا فوق `queueSave`.
- تصدير لوحة النتائج إلى Excel أو PDF.
- شهادات قابلة للطباعة للفائزين ولمن أكمل مسار التقدم.
- مشاركة بطاقة الطالب صورةً في واتساب.
- تقسيم الملف إلى وحدات مع خطوة بناء تُخرج ملفًا واحدًا — **يُطرح على المالك قبل التنفيذ**.
